📝 PHASE 1 : INSCRIPTION & RECHERCHE MÉDECIN [Tables: region, ville, secteur, type_etablissement, etablissement, domaine_medical, utilisateur, patient, dossier_medical]
👤 1.1 Création du compte patient
➡️ 1. Créer compte 🟡 Patient
🤖 INSERT INTO utilisateur 🤖 SystèmeSQLtable 7/21
📋 INSERT INTO patient 🤖 SystèmeSQLtable 8/21
⚡ id_dossier(PK) | id_patient(FK) | date_creation | antecedents_medicaux = NULL (فارغ) | antecedents_dentaires = NULL (فارغ) | notes_generales = NULL (فارغ)
⚡ [AUTO-TRIGGER] INSERT INTO dossier_medical (id_patient, date_creation) ⚡ Trigger automatiquetable 12/21 (DOSSIER VIDE)
✅ Compte actif + Dossier médical VIDE créé
🔍 1.2 RECHERCHE DU MÉDECIN après authentification [domaine → région → ville → secteur → établissement → médecin]
🔐 Patient authentifié (login) 🟡 Patient
🩺 Affiche les domaines médicaux disponibles 🤖 SystèmeSQLdomaine_medical
SELECT id_domaine, nom_domaine, icone FROM domaine_medical WHERE actif = TRUE ORDER BY nom_domaine
🩺 Patient choisit un domaine 🟡 Patient
🗺️ Affiche les régions qui ont des médecins de ce domaine 🤖 SystèmeSQLregion
SELECT DISTINCT r.id_region, r.nom_region FROM region r JOIN ville v ON v.id_region = r.id_region JOIN secteur s ON s.id_ville = v.id_ville JOIN etablissement e ON e.id_secteur = s.id_secteur JOIN medecin m ON m.id_etablissement = e.id_etablissement WHERE m.id_domaine = ? AND m.actif = TRUE
🗺️ Patient choisit une région 🟡 Patient
🏙️ Affiche les villes de cette région 🤖 SystèmeSQLville
SELECT DISTINCT v.id_ville, v.nom_ville FROM ville v JOIN secteur s ON s.id_ville = v.id_ville JOIN etablissement e ON e.id_secteur = s.id_secteur JOIN medecin m ON m.id_etablissement = e.id_etablissement WHERE v.id_region = ? AND m.id_domaine = ? AND m.actif = TRUE
🏙️ Patient choisit une ville 🟡 Patient
📍 Affiche les secteurs de cette ville 🤖 SystèmeSQLsecteur
SELECT s.id_secteur, s.nom_secteur FROM secteur s JOIN etablissement e ON e.id_secteur = s.id_secteur JOIN medecin m ON m.id_etablissement = e.id_etablissement WHERE s.id_ville = ? AND m.id_domaine = ?
📍 Patient choisit un secteur 🟡 Patient
🩺 Affiche les médecins + domaine médical + établissement 🤖 SystèmeSQLmedecin · etablissement · domaine_medical
SELECT m.id_medecin, m.nom, m.prenom, dm.nom_domaine, e.nom_etablissement, m.tarif_consultation, m.note_moyenne FROM medecin m JOIN etablissement e ON m.id_etablissement = e.id_etablissement JOIN domaine_medical dm ON m.id_domaine = dm.id_domaine WHERE e.id_secteur = ? AND m.id_domaine = ? AND m.actif = TRUE
🩺 Patient choisit un médecin 🟡 Patient
🏥 Affiche l'adresse de l'établissement (nom, adresse, téléphone) 🤖 SystèmeSQLetablissement
SELECT e.nom_etablissement, e.adresse, e.telephone, e.email FROM etablissement e JOIN medecin m ON m.id_etablissement = e.id_etablissement WHERE m.id_medecin = ?
✅ Médecin + Établissement sélectionnés → Prêt pour prise de RDV (Phase 4)
🩺 PHASE 2 : GESTION DES MÉDECINS [Tables: medecin, disponibilite]
🔐 Seul l'ADMIN peut créer un compte MÉDECIN
👤 2. Créer un médecin 🟠 Admin
INSERT INTO medecin (id_utilisateur, id_etablissement, id_domaine, nom, prenom, numero_ordre, tarif_consultation…) 🤖 Systèmetable 9/21
🔁 Pour chaque créneau de disponibilité du médecin
🗓️ Définir disponibilités 🟠 Admin
INSERT INTO disponibilite (id_medecin, jour_semaine, heure_debut, heure_fin) 🤖 Systèmetable 11/21

👤 3. Créer un réceptionniste 🟠 Admin
INSERT INTO receptionniste (id_utilisateur, nom, prenom, telephone) 🤖 Systèmetable 10/21
📅 PHASE 4 : PRISE & CONFIRMATION DE RENDEZ-VOUS [Table: rendez_vous]
📆 4. Prendre RDV 🟡 Patient OU 🟢 Réceptionniste
INSERT INTO rendez_vous (id_patient, id_medecin, date_heure, motif, statut='planifié') 🤖 Systèmetable 13/21
UNIQUE KEY (id_medecin, date_heure) — conflit de créneau bloqué par la contrainte DB, aucun verrouillage applicatif nécessaire
[ Confirmation par téléphone ]
📞 5. Confirmer RDV 🟢 Réceptionniste
UPDATE rendez_vous SET statut = 'confirmé' WHERE id_rdv = ?
[ Annulation ]
❌ Annuler RDV 🟡 Patient OU 🟢 Réceptionniste
UPDATE rendez_vous SET statut = 'annulé' WHERE id_rdv = ?
🩺 PHASE 5 : CONSULTATION MÉDICALE COMPLÈTE
🩺 5.1 PREMIÈRE CONSULTATION - REMPLISSAGE DU DOSSIER MÉDICAL [Table: dossier_medical]
📝 Le médecin interroge le patient et remplit : antecedents_medicaux, antecedents_dentaires
🔵 Médecin interroge le patient sur ses antécédents médicaux
📝 Médecin remplit antecedents_medicaux 🔵 Médecin
UPDATE dossier_medical SET antecedents_medicaux = 'Diabète type 2, Hypertension' WHERE id_patient = ?
📝 Médecin remplit antecedents_dentaires 🔵 Médecin
UPDATE dossier_medical SET antecedents_dentaires = 'Dévitalisation dent 16 en 2020, Extraction dent 38' WHERE id_patient = ?
✅ Dossier médical maintenant REMPLI (antecedents)

💰 PHASE 6 : FACTURATION & PAIEMENT [Tables: facture, paiement]
⚠️ montant_total est saisi MANUELLEMENT par la réceptionniste — il n'est jamais calculé automatiquement depuis soin.cout
🧾 6. Générer facture 🟢 Réceptionniste
INSERT INTO facture (id_patient, id_rdv, numero_facture, date_emission, montant_total) 🤖 Systèmetable 20/21
numero_facture FORMAT: FAC-YYYY-NNN | id_rdv nullable | montant_paye DEFAULT 0.00 | statut DEFAULT 'en attente'
[ Paiement complet ]
💳 Paiement 🟡 Patient
INSERT INTO paiement (id_facture, montant, mode_paiement) + UPDATE facture SET montant_paye = montant_total, statut='payée'table 21/21
mode_paiement ENUM: espèces | carte | virement | chèque
[ Paiement partiel ou échelonné ]
🔁 Pour chaque paiement
💳 Nouveau paiement
INSERT INTO paiement + UPDATE facture SET montant_paye = montant_paye + ?, statut = CASE WHEN montant_paye >= montant_total THEN 'payée' ELSE 'partiellement payée' END
